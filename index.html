Purpose

What it does

IdleWatcher watches Windows inactivity and display power state. When both safety conditions are met, it sends a shutdown request through the VoiceMeeter Remote API.

Idle-aware

Checks how long Windows has been inactive. The default threshold is 8 minutes and can be configured from 1 to 60 minutes.

Display-aware

Uses Windows display power notifications. A darkened or unknown display state is not treated as fully off.

VoiceMeeter-aware

Uses the Remote API and keeps monitoring if the VoiceMeeter engine is not running. The optional MacroButtons indicator is handled by a separate module.

Safety first

Two conditions. Both must be true.

The display state is a hard safety gate. Idle time alone can never trigger automatic shutdown.

✓ Display Off (0) + idle threshold reached

The watcher performs a final re-check and may send the shutdown command.

× Display On (1) or Dimmed (2)

Automatic shutdown is blocked, even when the idle threshold has elapsed.

× Unknown display state

Uncertainty means no shutdown. The watcher keeps monitoring.

Stopping IdleWatcher stops the automation process. It does not itself shut down VoiceMeeter.

Control flow

How the watcher makes its decision

A simplified view of the current modular flow. If the optional STATEONLY OFF write is accepted, the watcher allows 1000ms for MacroButtons to process it, then repeats the idle, display and graceful-stop checks immediately before the shutdown request.

Modular source layout

The current source separates orchestration, configuration, support services, API interop and the optional indicator into focused files.

Main watcher · PS1

Orchestrates the monitoring loop, engine state, safety checks and shutdown state machine.

Configuration · PSD1

Stores runtime settings and validated timing and behavior options.

Support module

Provides logging, startup status, graceful-stop signaling and refresh support.

Interop module

Finds the matching Remote API DLL, prepares the native C# source and manages API setup.

MacroButtons module

Owns the single STATEONLY writer. The indicator is optional and its failures are non-fatal.

Native C# + VBS

Defines Windows and VoiceMeeter interop, hidden launch and graceful stop.

Module contract

Import order is Support → Interop → MacroButtons. Keep the PS1, PSD1, VBS, three PSM1 modules and C# source together in one application folder. Before automatic shutdown, an accepted STATEONLY OFF write is followed by a 1000ms allowance and final idle/display/stop checks. API acceptance is not visual readback; the allowance does not guarantee a visible UI update.

Compatibility

Requirements

  • Windows.
  • Windows PowerShell 5.1.
  • VoiceMeeter installed.
  • The matching VoiceMeeter Remote API DLL.
  • Windows Script Host enabled for the VBS launcher.
Optional MacroButtons indicator

The optional STATEONLY write changes the indicator without executing the button macro. API acceptance is not visual readback, and the 1000ms pre-shutdown allowance does not guarantee that the UI has visibly updated. MacroButtons failures never block the core watcher.

Что делает программа

IdleWatcher следит за временем бездействия Windows и состоянием питания дисплея. Когда одновременно выполнены оба условия безопасности, утилита отправляет команду на выключение VoiceMeeter через Remote API.

Контроль бездействия

Порог по умолчанию: 8 минут. Его можно настроить в диапазоне от 1 до 60 минут.

Контроль дисплея

Используются системные уведомления Windows. Затемнённый или неизвестный статус не считается выключенным экраном.

Контроль VoiceMeeter

Работа идёт через Remote API. Если движок VoiceMeeter не запущен, наблюдатель продолжает мониторинг.

Два условия. Оба обязательны.

✓ Дисплей Off (0) + истёк порог бездействия

Перед отправкой команды выполняется финальная повторная проверка.

× Дисплей On (1) или Dimmed (2)

Автоматическое выключение заблокировано, даже если компьютер давно бездействует.

× Состояние дисплея неизвестно

Неопределённость означает запрет выключения. Наблюдатель продолжает работу.

Остановка IdleWatcher завершает только саму утилиту. Она не выключает VoiceMeeter.

Как принимается решение

Упрощённая схема текущего модульного процесса. Если API принимает команду STATEONLY OFF, watcher выдерживает паузу 1000 мс, чтобы MacroButtons успел обработать изменение, а затем непосредственно перед выключением повторно проверяет бездействие, состояние дисплея и запрос штатной остановки.

Подробная последовательность: необязательная команда STATEONLY OFF → пауза 1000 мс → финальная проверка idle/display/STOP → Command.Shutdown. Если условия безопасности изменились, выключение отменяется.

Модульная архитектура исходников

Текущая версия v1.0.6 разделяет программу по ответственности. Все файлы должны оставаться вместе в одной папке приложения.

Оркестратор · PS1

Главный цикл наблюдения, состояние VoiceMeeter, проверки безопасности и последовательность выключения.

Конфигурация · PSD1

Параметры запуска и интервалы с проверкой допустимых значений.

Support

Журналирование, статус запуска, сигналы штатной остановки и обновления.

Interop

Поиск DLL, подготовка и компиляция C# interop, вход в Remote API.

MacroButtons

Единственный writer для STATEONLY. Индикатор необязателен, его ошибки не блокируют watcher.

Native C# и VBS

Нативные объявления Windows/VoiceMeeter и скрытый запуск со штатной остановкой.

Важные границы

Порядок импорта модулей: Support → Interop → MacroButtons. Перед автоматическим выключением успешная команда STATEONLY OFF сопровождается паузой 1000 мс, после которой выполняется финальная проверка idle/display/STOP. Принятие команды API не является считыванием видимого состояния, а пауза не гарантирует обновление интерфейса.

Требования

  • Windows.
  • Windows PowerShell 5.1.
  • Установленный VoiceMeeter.
  • Подходящая DLL VoiceMeeter Remote API.
  • Включённый Windows Script Host для VBS-запускателя.
Необязательный индикатор MacroButtons

Режим STATEONLY меняет индикацию, не запуская макрос. Принятие команды API не подтверждает фактическое отображение состояния, а пауза 1000 мс перед выключением не гарантирует визуального обновления. Ошибки MacroButtons не мешают основной работе наблюдателя.
